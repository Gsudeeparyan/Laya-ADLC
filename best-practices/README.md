# Best practices for AI at Laya

Everything Laya knows about using AI well, in one place. Each document links to its sources, and [sources.md](sources.md) lists them all with the date they were checked.

## The ten rules

These apply to everyone, whichever Copilot you use.

1. **A named person answers for everything.** AI does the work; you own the result. "Copilot wrote it" isn't an explanation.
2. **Give it the source.** AI guesses when it isn't given the facts, and it guesses convincingly.
3. **Check in proportion to the risk.** The more it matters, the harder you check. See the [risk tiers](../roles-and-lifecycle/risk-tiers.md).
4. **Keep personal data out unless the job needs it.** If it does, clean it first. Health data needs the most care.
5. **People decide about people.** Claims, cover, prices, complaints, jobs and performance stay with people.
6. **Use only Laya's Copilot.** Look for the green shield. Personal accounts and other AI websites don't have the same protections.
7. **Treat what AI reads as information, not instructions.** Files, emails, web pages and tickets can contain hidden instructions aimed at AI.
8. **Work in small steps.** Small changes are easier to check, and easier to undo.
9. **Turn mistakes into checks.** If a machine could catch it next time, make a machine catch it. Otherwise, write it down.
10. **Say so when it goes wrong, the same day.** It's about speed, not blame.

## How this stays right

Microsoft and GitHub change quickly: several things here changed in the months before it was written. So:

- The library owner re-checks [sources.md](sources.md) **every quarter**.
- Regulation is reviewed by Compliance, and it's marked as a draft until they have.
- Where sources disagree, the document says so, and doesn't pick quietly.
- Anything Laya hasn't decided is marked **[to confirm]**.

Found something wrong or out of date? Tell the library owner or your AI champion.
